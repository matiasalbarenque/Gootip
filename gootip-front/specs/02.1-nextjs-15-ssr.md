# SPEC 02.1 — Next.js 15 and local SSR validation

> **Status:** Implemented
> **Depends on:** [Front SPEC 02](02-login-page.md) for the existing `/login` route.
> **Date:** 2026-11-05
> **Objective:** Keep the frontend on a patched Next.js 15 release for AWS Amplify compatibility, align its dependencies, and verify request-time rendering with the local production server.

## Scope

- Pin Next.js 15, as required by AWS Amplify's officially supported maximum version, and keep the existing App Router.
- Review direct runtime and development dependencies against the selected Next.js version and the repository's Node and pnpm toolchain.
- Add `/health/ssr` and check the existing home and login routes against the local production build.

## Implementation plan

1. **Pin Next.js 15 for AWS Amplify.** Amplify's officially supported maximum Next.js version is 15. Select the newest stable patched Next.js 15 release at implementation time using the official releases and security advisories. Pin the exact version in `gootip-front/package.json` and update `gootip-front/pnpm-lock.yaml` with the pinned pnpm. [Next.js releases](https://github.com/vercel/next.js/releases) · [Security advisories](https://github.com/vercel/next.js/security/advisories)
2. **Review and update frontend dependencies.** Review every entry in `dependencies` and `devDependencies` using package metadata, release notes, and security advisories. Check peer and engine requirements against the selected Next.js version, Node from `.nvmrc`, and pnpm from the frontend manifest. Review React, React DOM, and their types together. Include TypeScript, Node types, Tailwind, PostCSS, UI packages, and lint and formatting tools. Prefer secure patch or minor releases within compatible majors. Change majors when compatibility, security, or upstream support requires it. Record why any newer major is deferred. Update exact pins and the lockfile, then run a clean frozen install, lint, format check, type check, and a production build.
3. **Verify request-time rendering locally.** Add `/health/ssr` as a Node.js Server Component with `dynamic = 'force-dynamic'`. Render a UUID generated for each request without calling the backend. Start the production build with `pnpm start` and run the HTTP checks below. [Next.js 15 route configuration](https://nextjs.org/docs/15/app/api-reference/file-conventions/route-segment-config)

## Acceptance criteria

- [x] The frontend manifest and lockfile pin the selected patched Next.js 15 release and the reviewed compatible dependencies. Any deferred major update has a recorded reason.
- [x] `pnpm install --frozen-lockfile`, `pnpm lint`, `pnpm format:check`, `pnpm exec tsc --noEmit`, and `pnpm build` pass using the pinned toolchain.
- [x] The local production server returns `200` for `/` and `/login`, serves their assets, and returns `404` for an unknown path.
- [x] Two requests to the same local `/health/ssr` URL return `200` and contain distinct UUIDs in the raw HTML without executing browser JavaScript.

## Risks

- Keep the selected Next.js release within AWS Amplify's officially supported version range; re-evaluate this pin if Amplify adds support for a newer major.

## Deferred work

- Hosting and release automation belong to a separate spec, including AWS provisioning, the Git provider connection, and any GitHub Actions workflow.
- Live Better Auth integration belongs to [Front SPEC 03](03-better-auth-bearer-client.md).

# SPEC 03.2 — Terraform Initialization and Verification Latency Reduction

> **Status:** Implemented
> **Depends on:** SPEC 02.1, SPEC 02.3, SPEC 03.1
> **Date:** 2026-10-17
> **Objective:** Make the verification that follows every edit take seconds by reusing a cached provider and a fast, plan-free loop, without removing any final validation.

## Why this spec exists

The isolated evaluator renders every Gootip IAM configuration through
`scripts/iam_policy_evaluator.py`, which creates a fresh temporary directory and
runs a full `terraform init -reconfigure` for every render. A single render costs
about 14 seconds (init ≈ 8s, plan ≈ 5–6s), and the full local verification runs
many of them.

Measured on the reference machine with a warm provider cache:

| Operation                 | Command                                                       | Wall clock                         |
| ------------------------- | ------------------------------------------------------------- | ---------------------------------- |
| One isolated render       | `render_plan(BOOTSTRAP_MAXIMUM)`                              | ≈ 14s                              |
| Guardrail checker         | `python3 scripts/check_iam_policy_guardrails.py`              | ≈ 86s (6 renders)                  |
| Split comparator          | `python3 bootstrap/scripts/compare_bootstrap_policy_split.py` | ≈ 14s (1 render)                   |
| Unit suite                | `python3 -m unittest discover -s scripts/tests`               | ≈ 14s (1 render + pure tests < 1s) |
| Full offline verification | checker + comparator + render test                            | ≈ 2 min                            |

Two facts drive this spec:

- `TF_PLUGIN_CACHE_DIR` is empty in the environment. When it is set, `terraform
  init` reuses the cached AWS provider instead of downloading it again (on this
  machine the provider directory becomes a symlink into
  `~/.terraform.d/plugin-cache`).
- Only one test in `scripts/tests` materializes Terraform
  (`test_render_plan_materializes_policies_and_cleans_up`); every other test is
  pure. Running that one test in the fast edit cycle costs ≈ 15s for no editing
  feedback.

This spec only removes that waste. It changes no policy, no resource, no
provider or Terraform version, no threshold, and no guardrail.

## Scope

**In:**

- Make `scripts/iam_policy_evaluator.py` reuse a provider cache: it honors
  `TF_PLUGIN_CACHE_DIR` when it is set and otherwise uses and creates
  `~/.terraform.d/plugin-cache`.
- Add a fast edit-cycle script `scripts/verify_fast.sh` that runs
  `terraform fmt -check -recursive`, both `terraform validate` invocations, and
  only the pure Python tests, selected from the command.
- Add a full offline verification script `scripts/verify_full.sh` that runs the
  fast cycle, the guardrail checker, the split comparator, and the render test.
- Add two pure unit tests that prove `plugin_cache_env()` behavior.
- Document the fast cycle, the full offline cycle, and the separate live-AWS
  gate in `README.md`, `bootstrap/README.md`, and
  `.agents/skills/project-conventions/SKILL.md`.

**Out of scope (for future specs):**

- A batched render, `render_roots`, memoization, a plan cache keyed by hash, or
  sharing `BOOTSTRAP_MAXIMUM` between processes.
- Merging the checker and the comparator into one driver: they stay
  independent.
- CI/CD implementation (SPEC 11).
- Any change to IAM policies, AWS resources, backend configuration, Terraform
  or provider versions, thresholds, or security behavior.

## Data model

This feature introduces no persisted data structures and no new Terraform
inputs. It adds one environment contract, one evaluator helper, two scripts, and
two unit tests.

### Provider cache contract

- `TF_PLUGIN_CACHE_DIR` is read from the environment.
- When it is non-empty, its value is passed to every `terraform init` unchanged.
- When it is empty, the evaluator uses `DEFAULT_PLUGIN_CACHE_DIR`, which is
  `~/.terraform.d/plugin-cache`, and creates it if it does not exist.

```python
# scripts/iam_policy_evaluator.py
import os

DEFAULT_PLUGIN_CACHE_DIR = Path.home() / ".terraform.d" / "plugin-cache"

def plugin_cache_env() -> dict[str, str]:
    """Return the subprocess environment with a provider cache configured."""
    env = dict(os.environ)
    cache = env.get("TF_PLUGIN_CACHE_DIR") or str(DEFAULT_PLUGIN_CACHE_DIR)
    Path(cache).mkdir(parents=True, exist_ok=True)
    env["TF_PLUGIN_CACHE_DIR"] = cache
    return env
```

The helper is the only place that decides the cache location. `_run_terraform_plan`
passes `env=plugin_cache_env()` to its `terraform init` subprocess.

### New unit tests

`scripts/tests/test_iam_policy_guardrails.py` gains a pure test case:

- `PluginCacheTests.test_plugin_cache_env_respects_override` sets
  `TF_PLUGIN_CACHE_DIR` to a temporary path and asserts the helper returns it
  unchanged and creates it.
- `PluginCacheTests.test_plugin_cache_env_creates_default_when_unset` clears the
  variable, patches `evaluator.DEFAULT_PLUGIN_CACHE_DIR` to a temporary path, and
  asserts the helper returns that default and creates it.

Both tests are pure: they call no `render_plan`, do not materialize Terraform,
and make no AWS request. They are part of the fast cycle.

### Scripts

`scripts/verify_fast.sh`:

```bash
#!/usr/bin/env bash
set -euo pipefail

ROOT="$(cd "$(dirname "${BASH_SOURCE[0]}")/.." && pwd)"
cd "$ROOT"

# Reuse one provider cache; create the default only when the caller set none.
export TF_PLUGIN_CACHE_DIR="${TF_PLUGIN_CACHE_DIR:-$HOME/.terraform.d/plugin-cache}"
mkdir -p "$TF_PLUGIN_CACHE_DIR"

terraform fmt -check -recursive

[ -d .terraform ] || terraform init -backend=false
terraform validate

[ -d bootstrap/.terraform ] || terraform -chdir=bootstrap init -backend=false
terraform -chdir=bootstrap validate

# Pure tests only: no Terraform plan is materialized.
uv run --with pytest==9.1.1 pytest -q \
  -k 'not test_render_plan_materializes_policies_and_cleans_up' scripts/tests
```

`scripts/verify_full.sh`:

```bash
#!/usr/bin/env bash
set -euo pipefail

HERE="$(cd "$(dirname "${BASH_SOURCE[0]}")" && pwd)"
cd "$(cd "$HERE/.." && pwd)"

"$HERE/verify_fast.sh"

# Every configuration, threshold, and guardrail is preserved.
python3 scripts/check_iam_policy_guardrails.py
python3 bootstrap/scripts/compare_bootstrap_policy_split.py
uv run --with pytest==9.1.1 pytest -q \
  -k 'test_render_plan_materializes_policies_and_cleans_up' scripts/tests
```

Neither script pipes through `tail`, `sed`, or any pipeline that hides an exit
code. Both stop at the first error and stream its real output. Neither requires
credentials or makes an AWS call.

### Live-AWS gate (separate, not part of the offline full cycle)

The following commands make AWS requests and are documented as a separate,
mandatory gate before relevant IAM plans or applies. They are not run by
`scripts/verify_full.sh`:

- `terraform -chdir=bootstrap test`, run from the bootstrap MFA session that
  corresponds to the bootstrap role.
- `python3 scripts/validate_policies.py --profile <PROFILE>`, run with a
  principal explicitly authorized for `access-analyzer:ValidatePolicy`.

The two commands are not assumed to use the same profile. In the standing
configuration, `gootip-bootstrap-admin` does not hold
`access-analyzer:ValidatePolicy`, so it is not presented as the profile for
`validate_policies.py`.

## Decisions

- **Yes:** reuse the provider through `TF_PLUGIN_CACHE_DIR`, with an
  overrideable default of `~/.terraform.d/plugin-cache`.
- **Yes:** pin the test runner to `pytest==9.1.1` in both scripts.
- **Yes:** select the pure tests from the command with `pytest -k`; introduce no
  environment skip and change no test behavior.
- **Yes:** keep the checker and the comparator as independent scripts.
- **Yes:** require provider reuse ("the second render does not re-download the
  provider") as the portable criterion, and record the symlink as this-machine
  evidence only.
- **Yes:** treat the `< 15s` figure as a reference measurement for this machine,
  not a portable gate.
- **No (deferred):** batched render, `render_roots`, memoization, a plan cache
  keyed by hash, and sharing `BOOTSTRAP_MAXIMUM` between processes.

## Risks

| Risk                                               | Mitigation                                                                                   |
| -------------------------------------------------- | -------------------------------------------------------------------------------------------- |
| The cache holds a different provider version       | It becomes a cache miss: still correct, only slower.                                         |
| `pytest` is not installed on another machine       | `uv run --with pytest==9.1.1` fetches and caches it once; the cycle still makes no AWS call. |
| `uv` is unavailable                                | Document native `pytest -k` with the same selection and pinned version as an equivalent.     |
| The default cache directory does not exist yet     | `plugin_cache_env()` creates it before `terraform init`.                                     |
| The auto-init reaches the network on the first run | Only the first run per root; documented, and `-backend=false` never touches the backend.     |

## What is **not** in this spec

- A batched render, `render_roots`, memoization, or any plan cache.
- Sharing `BOOTSTRAP_MAXIMUM` between the checker and the comparator, or merging
  them into one driver.
- Any change to IAM policies, AWS resources, backend configuration, Terraform or
  provider versions, thresholds, or security behavior.
- The live-AWS gate itself (`terraform test` and `validate_policies.py`); this
  spec only documents it as separate.
- CI/CD implementation (SPEC 11).

Each of those, if it lands, goes in its own spec or in the deferred second stage
of this one.

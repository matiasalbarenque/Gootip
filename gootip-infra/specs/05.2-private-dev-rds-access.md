# SPEC 05.2 — Private Dev RDS Workstation Access

> **Status:** Implemented
> **Depends on:** SPEC 02.1, SPEC 02.2, SPEC 05.1
> **Date:** 2026-10-19
> **Objective:** Provide MFA-authorized on-demand access from a developer workstation to the private dev RDS instance through a stopped-by-default private tunnel host without exposing the database or adding general VPC internet access.

## Why this spec exists

The dev PostgreSQL instance is deliberately private, has no public route, and accepts port 5432 only from approved VPC clients. SPEC 05.1 creates the dedicated human database identity but does not create a workstation-to-VPC path.

An occasional DBeaver workflow does not justify a permanent VPN, NAT Gateway, public bastion, or public RDS endpoint. This spec adds a narrow management path using EC2 Instance Connect Endpoint and a private EC2 host that runs only while an operator session needs it.

## Scope

**In:**

- One EC2 Instance Connect Endpoint in the existing dev VPC.
- One minimal private Amazon Linux tunnel host, stopped outside operator sessions.
- Security groups permitting only Instance Connect SSH and PostgreSQL forwarding.
- Least-privilege deployment permissions for the new tagged resources.
- Least-privilege session permissions added to `GootipDatabaseOperator`.
- A local helper for discovery, start, tunnel, password retrieval, information, and recovery stop operations.
- Reuse of the verified regional RDS CA bundle.
- DBeaver Community-compatible password retrieval and verified PostgreSQL TLS configuration.
- Focused Terraform, IAM, helper, connectivity, TLS, authorization, lifecycle, and cost-state validation.

**Out of scope:**

- Creating or changing the PostgreSQL operator role, secret, or data grants; SPEC 05.1 owns those.
- Public RDS access, a public bastion, Internet Gateway, NAT Gateway, Client VPN, Site-to-Site VPN, or Direct Connect.
- Systems Manager managed nodes or SSM interface endpoints.
- A general-purpose shell host, build runner, application runtime, proxy, or persistent administration environment.
- DBeaver PRO-only AWS IAM or SSM integrations.
- Staging or production access.
- Always-on connectivity or sessions longer than one hour.

## Data model and integration contracts

### AWS resources

| Resource                      | Contract                                                                                             |
| ----------------------------- | ---------------------------------------------------------------------------------------------------- |
| EC2 Instance Connect Endpoint | `gootip-dev-db-eice`, IPv4, private subnet index `0`, client-IP preservation disabled                |
| Tunnel instance               | `gootip-dev-db-tunnel`, `t4g.micro`, reviewed pinned Amazon Linux 2023 ARM64 AMI                      |
| Root volume                   | 8 GiB `gp3`, encrypted, deleted with the instance                                                    |
| Instance networking           | No public IPv4, no additional ENI, no instance profile, IMDSv2 required                              |
| Power behavior                | Stopped outside operator sessions; instance-initiated shutdown behavior is `stop`                    |
| Endpoint security group       | Egress TCP 22 only to the tunnel-host security group                                                 |
| Tunnel security group         | Ingress TCP 22 only from the endpoint security group; egress TCP 5432 only to the RDS security group |
| RDS security group            | Additional ingress TCP 5432 only from the tunnel-host security group                                 |

The endpoint and instance remain in the existing private topology. No route table receives an Internet Gateway, NAT, or public default route. The tunnel host has no general outbound access and cannot reach Secrets Manager; the local workstation retrieves the operator secret through the AWS API.

The tunnel host has no workload IAM credentials. Amazon Linux supplies SSH and EC2 Instance Connect support in the pinned image; package installation at boot is forbidden because the subnet has no internet egress.

### Terraform interface

The application root adds these non-sensitive inputs:

| Variable                           | Contract                                                                            |
| ---------------------------------- | ----------------------------------------------------------------------------------- |
| `database_operator_access_enabled` | Boolean gate, default `false`, enabled only by `environments/dev.tfvars`            |
| `db_tunnel_ami_id`                 | Explicit reviewed `ami-*` value in `us-east-2`; no automatic latest-AMI replacement |
| `db_tunnel_instance_type`          | Defaults to `t4g.micro` and validates the approved dev choice                        |

It publishes these non-sensitive outputs when enabled:

- `db_tunnel_instance_id`
- `db_instance_connect_endpoint_id`
- `db_endpoint`

The bootstrap deployment policy adds only the EC2 actions required to create, tag, read, update, and delete the tunnel resources. Creation-time wildcard exceptions follow the repository rule: exact action, region, required request tags, exact tag-key allowlist, and no wildcard `PassRole`.

If the EC2 Instance Connect service-linked role is absent, `GootipBootstrapAdmin` receives a temporary exact `iam:CreateServiceLinkedRole` permission for `ec2-instance-connect.amazonaws.com`. The role is created externally once, is never managed or imported by Terraform, and the temporary permission is then removed.

### Operator IAM contract

SPEC 05.2 extends `GootipDatabaseOperator` with only:

- `ec2:DescribeInstances`, `ec2:DescribeInstanceStatus`, and `ec2:DescribeInstanceConnectEndpoints` in `us-east-2`.
- `rds:DescribeDBInstances` in `us-east-2` for the exact dev identifier discovery flow.
- `ec2:StartInstances` and `ec2:StopInstances` for the instance tagged `project=gootip`, `env=dev`, and `purpose=db-tunnel`.
- `ec2-instance-connect:SendSSHPublicKey` for the tagged tunnel instance with `ec2:osuser=ec2-user`.
- `ec2-instance-connect:OpenTunnel` for the tagged endpoint with remote port `22` and maximum duration no greater than 3,600 seconds.

It receives no `RunInstances`, `TerminateInstances`, `PassRole`, security-group mutation, RDS mutation, IAM mutation, state access, or broader secret access.

### Local helper contract

`gootip-infra/scripts/db_access.sh` is the sole documented workstation entry point. It always uses profile `gootip-db-operator` and Region `us-east-2`; neither account, region, resource IDs, database identifier, remote port, nor profile can be redirected by untrusted input.

| Command    | Behavior                                                                                                                                                                |
| ---------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `info`     | Discovers the exact tagged resources, verifies/extracts the existing reviewed RDS CA archive, and prints only non-sensitive DBeaver settings                            |
| `tunnel`   | Starts the host if stopped, waits until EC2 reports it running, opens `127.0.0.1:15432` to the RDS endpoint on 5432 through `aws ec2-instance-connect ssh`, and remains in the foreground; SSH connectivity confirms OS readiness without waiting for the slower EC2 status checks |
| `password` | Reads the exact operator secret and writes only its password as the first stdout line for DBeaver shell-command authentication                                          |
| `stop`     | Stops the exact tagged tunnel host after confirming its identity; used for recovery after an interrupted session                                                        |

`GOOTIP_DB_LOCAL_PORT` may override only the local listening port and must validate to an unprivileged integer port. The default is `15432`. Remote SSH remains `22`, remote PostgreSQL remains `5432`, and the database identifier remains `gootip-dev`.

The helper tracks the instance's initial state. Its `EXIT`, `INT`, and `TERM` cleanup stops the instance only when that invocation started it. A failed tunnel after a successful start executes the same cleanup. A pre-existing running session is never stopped implicitly by a second helper process.

OpenSSH host-key verification remains enabled. First use follows normal trust-on-first-use behavior; later key mismatches fail rather than bypass verification.

The CA is extracted from the already checksummed `rds-ca-layer.zip` into ignored local path `.db-access/rds-ca-bundle.pem`. The helper runs the existing archive verifier first and never treats a failed or missing checksum as usable TLS material.

### DBeaver contract

| Setting                   | Value                                                                          |
| ------------------------- | ------------------------------------------------------------------------------ |
| Driver                    | PostgreSQL                                                                     |
| Host                      | `localhost`                                                                    |
| Port                      | `15432` or the validated local override                                        |
| Database                  | `gootip`                                                                       |
| Username                  | `gootip_dev_operator`                                                          |
| Authentication            | Password from shell command using the absolute path to `db_access.sh password` |
| Saved password            | Disabled                                                                       |
| SSL mode                  | `verify-full`                                                                  |
| CA certificate            | Absolute `.db-access/rds-ca-bundle.pem` path reported by `info`                |
| Certificate hostname      | Actual RDS endpoint reported by `info`                                         |
| Skip hostname validation  | Disabled                                                                       |
| Verify server certificate | Enabled                                                                        |

DBeaver does not own the SSH session. The operator starts `db_access.sh tunnel` in a terminal before connecting and ends it with `Ctrl-C` after disconnecting.

## Acceptance criteria

- [x] RDS remains `publicly_accessible = false` and receives no CIDR-based workstation or internet ingress.
- [x] The VPC gains no Internet Gateway, NAT Gateway, public subnet, public default route, Client VPN, or SSM endpoint.
- [x] The tunnel instance has no public IP, instance profile, or general outbound security-group rule.
- [x] IMDSv2 is mandatory and the encrypted root volume is the only persistent host storage.
- [x] Endpoint-to-host traffic is limited to TCP 22 and host-to-RDS traffic is limited to TCP 5432 through security-group references.
- [x] The deployment role cannot pass a role or create arbitrary untagged tunnel resources.
- [x] `GootipDatabaseOperator` can discover, start, stop, and tunnel only through the intended tagged dev resources.
- [x] Operator tunnel authorization limits the remote port to 22, OS user to `ec2-user`, and session duration to at most one hour.
- [x] The helper refuses missing, duplicate, wrong-account, wrong-region, wrong-tag, or unexpected-state resources.
- [x] `db_access.sh password` emits only the password on stdout and emits no secret JSON, ARN, username, or diagnostic there.
- [x] DBeaver stores no database password and retrieves it through the helper.
- [x] PostgreSQL TLS is configured for `verify-full`, the reviewed regional CA, and the real RDS certificate hostname despite connecting through `localhost`.
- [x] Wrong CA and wrong certificate hostname tests fail.
- [x] A normal tunnel exit stops the instance when that invocation started it.
- [x] A failed or interrupted session has a tested recovery path and does not stop a host that was already running.
- [x] Live SQL proves ordinary application DML, migration-history read-only behavior, and DDL/role/undeclared-schema denial from SPEC 05.1.
- [x] CloudTrail contains the relevant start/stop, public-key, and tunnel attempts without exposing database credentials.
- [x] The exact saved plan contained only expected creates and was applied by filename.
- [x] Focused checks and final Terraform plans pass with no unexplained drift.

## Closure evidence

Verified in dev on 2026-10-20:

- The positive TLS connection used `verify-full`, the reviewed regional CA, the real RDS certificate hostname, TLS 1.3, and `gootip_dev_operator`. Independent wrong-CA and wrong-hostname connections both failed certificate validation.
- Live SQL in an explicit transaction proved ordinary `auth` table `SELECT`, `INSERT`, `UPDATE`, and `DELETE`; migration-history `SELECT`; and denial of migration writes, `TRUNCATE`, auth/undeclared-schema DDL, `CREATE ROLE`, and `ALTER ROLE`. The transaction was rolled back and left no probe row.
- The tunnel helper returned the host to `stopped` after the foreground session ended.
- `scripts/verify_full.sh` passed with 113 tests, one intentionally deselected test, 26 subtests, and zero IAM guardrail failures. Focused policy-comparator tests passed, TFLint reported no findings, and the SPEC 05.2 Terraform file reported zero Trivy misconfigurations.
- Refresh-free and normal plans for both the application and bootstrap roots completed with `No changes`; the normal plans refreshed the live AWS resources and found no unexplained drift.

## Decisions

- **Yes:** use EC2 Instance Connect Endpoint plus a minimal private EC2 host for occasional workstation access.
- **Yes:** keep the tunnel host stopped outside sessions and make the foreground helper responsible for normal lifecycle cleanup.
- **Yes:** keep DBeaver separate from SSH lifecycle and use its Community-compatible password-from-command feature.
- **Yes:** preserve `verify-full` by supplying the real RDS certificate hostname separately from `localhost`.
- **Yes:** pin the AMI ID explicitly so a routine plan cannot replace the host because a new image was published.
- **No:** make RDS public, even temporarily.
- **No:** add NAT, a public bastion, Client VPN, or SSM endpoints for this occasional dev workflow.
- **No:** attach IAM credentials to the tunnel host or turn it into a general administrative machine.
- **No:** use DBeaver PRO-only AWS integrations or persist the database password in DBeaver.

## Risks

| Risk                                                          | Mitigation                                                                                                                              |
| ------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------- |
| An interrupted helper leaves the instance running             | Use cleanup traps, an explicit `stop` command, state-aware ownership, and a documented final state check.                               |
| TLS hostname validation fails through `localhost`             | Configure DBeaver's certificate hostname with the actual RDS endpoint and test wrong-host rejection.                                    |
| A broad EC2 permission becomes an escalation path             | Separate deployment and operator policies, require tags/region/exact conditions, and forbid `PassRole` and arbitrary instance creation. |
| A new AMI causes an unexpected replacement                    | Pin the reviewed regional AMI ID and update it only through a separate reviewed plan.                                                   |
| The host cannot install or patch packages without egress      | Use a reviewed image containing the required software and replace the disposable host deliberately when updating it.                    |
| A second tunnel process stops a shared host                   | Stop automatically only when the current process changed the host from stopped to running.                                              |
| A tunnel is mistaken for high-volume application connectivity | Keep one-hour limits, a stopped-by-default host, and documentation that this is management traffic only.                                |

## What is **not** in this spec

- Public database access, public bastions, NAT, VPN, Direct Connect, or SSM connectivity.
- Application traffic, CI runners, migration execution, backups, or a permanent administration host.
- PostgreSQL identity or grant creation; SPEC 05.1 owns that contract.
- Staging, production, sessions longer than one hour, or always-on desktop connectivity.

# SPEC 02.4 — Automatic MFA Renewal for Local AWS Access

> **Status:** Implemented
> **Depends on:** SPEC 02, SPEC 02.1
> **Date:** 2026-10-18
> **Objective:** Prompt for a three-hour MFA source session when entering `gootip-infra/` only if the existing session has expired, request one-hour assumed-role sessions, and preserve the existing AWS profile workflow.

## Why this spec exists

The current workflow selects `gootip-terraform-deploy` through direnv, but the
operator must manually clear inherited AWS variables and renew `gootip-mfa`.
SPEC 02.1 limits the MFA source session and the maximum MFA age in the shared
human-role trust policy to one hour. This spec extends the source session and the
MFA-age ceiling to three hours and keeps each assumed-role session at one hour —
AWS's hard cap for sessions assumed by role chaining. It does not replace
SPEC 02.1's identity, authorization, or state model.

## Scope

**In:**

- An interactive zsh entry hook for `gootip-infra/` and its descendants, installed once per machine, which checks the `gootip-mfa` source session when entering the tree or starting an interactive shell inside it.
- Reuse a valid session without prompting. Prompt for MFA only when the source profile is missing or AWS explicitly reports its token expired.
- A manual `gootip-mfa-refresh` command that renews the source session while the operator remains in the directory.
- Three-hour MFA source credentials and a three-hour maximum MFA age in the shared human-role trust policy, with one-hour assumed-role sessions for both `GootipTerraformDeploy` and `GootipBootstrapAdmin`.
- Request one-hour role sessions in both local role profiles, and document the independent source and role credential lifetimes and the role-chaining limit.
- Offline tests, operator setup and recovery documentation, a reviewed bootstrap plan, and separately authorized live validation.

**Out of scope:**

- IAM Identity Center, AWS SSO, new identities or roles, policy permission expansions, and changes to Terraform state or application infrastructure.
- Automatic MFA challenges before every command, or saving the MFA seed or one-time code.
- Running interactive login through `.envrc`, changing its profile selection, or modifying other projects' AWS configuration.
- Committing account identifiers, MFA device ARNs, credentials, tokens, or local shell and AWS configuration files.

## Data model and integration contracts

| Location                                                             | Contract                                                                                                                                             |
| -------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------- |
| `gootip-infra/.envrc`                                                | Retain `AWS_PROFILE=gootip-terraform-deploy` and existing enter/leave restoration.                                                                   |
| `gootip-infra/scripts/gootip-mfa.zsh`                                | Versioned interactive hook and `gootip-mfa-refresh` function; installation sources this file from local `~/.zshrc`.                                  |
| `~/.aws/credentials`                                                 | Existing `gootip-dev` and `gootip-mfa` profiles; AWS CLI writes temporary source credentials to `gootip-mfa`.                                        |
| `~/.aws/config`                                                      | Existing role profiles use `gootip-mfa` and request `duration_seconds = 3600` (one hour). Store the MFA device ARN locally, never in the repository. |
| `gootip-infra/bootstrap/iam.tf` and `bootstrap/tests/iam.tftest.hcl` | Raise the shared MFA-age condition to 10,800 seconds, keep both role maximum session durations at 3,600 seconds, with matching tests.                |
| `gootip-infra/README.md` and `gootip-infra/bootstrap/README.md`      | Setup, renewal, independent lifetimes, error handling, rollout, and recovery.                                                                        |

The hook operates only in interactive zsh with a usable terminal. It checks on a transition from outside the project tree to inside, or once at shell startup inside the tree; moving between descendants does not repeatedly prompt. It does not run in CI, non-interactive shells, or `direnv exec`. Automatic verification is a bounded read-only STS call against `gootip-mfa`, not against a cached assumed-role session. Classify a missing source profile or an explicit expired-token response as requiring renewal. Network failures, access errors, malformed credentials, missing tools, and unrecognized failures must produce a clear error and never be treated as expiration. Verification must not print credentials, tokens, or account identifiers.

Run verification and renewal in a child environment that removes `AWS_ACCESS_KEY_ID`, `AWS_SECRET_ACCESS_KEY`, `AWS_SESSION_TOKEN`, `AWS_SECURITY_TOKEN`, and `AWS_PROFILE`; explicitly select the intended profile. Do not unset these variables in the parent shell. Preserve existing direnv behavior and other profiles. Pass the locally configured MFA device ARN to `aws configure mfa-login --profile gootip-dev --duration-seconds 10800 --update-profile gootip-mfa`. If the device ARN is missing, give a setup instruction and do not guess it. Renew only through an interactive terminal; cancellation or failure leaves the shell usable and reports failure without claiming success. The role profiles assume roles through the `gootip-mfa` session, so AWS caps each assumed-role session at one hour (role chaining); the profiles therefore request one hour, and a larger request fails.

`GetSessionToken` source credentials and `AssumeRole` credentials have independent expiration times. An assumed role issued near the end of the source session can remain usable after the source credentials expire; the three-hour MFA-age condition is checked when the role is assumed, not continuously. Do not describe three hours as a shared hard cutoff. AWS caps a role session assumed by role chaining — including assumption from the `gootip-mfa` `GetSessionToken` credentials — at one hour, so each assumed-role session lasts one hour while the three-hour source session is reused for further hourly assumptions without another MFA prompt. Existing cached role credentials may persist across renewal, so validation must force fresh role assumptions without deleting unrelated caches.

## Implementation plan

1. Document the current one-hour flow and prepare offline fixtures for valid, missing, expired, unreachable, and denied source sessions. Define isolated temporary AWS configuration and fake CLI responses for tests; never use real credentials in fixtures.
2. Add the interactive zsh helper and manual renewal function. Verify entry, descendant transitions, shell startup, cancellation, missing ARN, environment isolation, and non-interactive behavior using isolated tests.
3. Raise the bootstrap IAM trust MFA-age ceiling to 10,800 seconds, keep both role maximum session durations at 3,600 seconds, and update the existing IAM tests. Verify Terraform formatting and offline validation; inspect a bootstrap plan for only the intended trust change.
4. After the required explicit approval for the reviewed AWS change, apply the bootstrap change using the existing authorized workflow. Preserve the existing one-hour login procedure until this step succeeds. Provide rollback to the previous trust and role durations if validation fails.
5. Configure the two local role profiles to request 3,600 seconds (one hour) and install the zsh hook only after the AWS limits are in place. Preserve other settings and make local configuration changes reversible. Establish local MFA-device configuration without placing the ARN in tracked files.
6. Mint a new MFA source session, force fresh assumptions for each role, and verify the effective identities and requested one-hour durations without exposing credentials. Repeat a fresh role assumption after the MFA source session has aged beyond one hour and before it reaches three hours, proving the assumption needs no new MFA code. Document setup, manual renewal, failures, rollback, and the limits of validation.

## Acceptance criteria

- [ ] Entering the directory with a valid `gootip-mfa` session does not request an MFA code; a missing or explicitly expired session requests one once.
- [ ] Entering with an unknown, network, authorization, or malformed-credential error prints an actionable error, does not launch MFA login, and leaves the shell usable.
- [ ] Moving inside the project tree does not trigger a new login; starting an interactive shell inside the tree checks once; non-interactive shells and `direnv exec` never prompt.
- [ ] `gootip-mfa-refresh` requests a code and updates only `gootip-mfa`; cancellation or failed authentication is reported without claiming success.
- [ ] Inherited AWS credential variables do not affect verification or renewal, and their parent-shell values remain unchanged. Direnv still selects and restores `AWS_PROFILE` as before.
- [ ] Source login requests 10,800 seconds. Both role profiles request 3,600 seconds, both role maximums permit 3,600-second sessions, and the shared trust requires present MFA with age at most 10,800 seconds.
- [ ] A fresh three-hour MFA source session can assume both intended roles immediately and again with MFA age greater than 3,600 seconds and less than 10,800 seconds, without a new MFA code. Each role session lasts one hour, and each validation bypasses stale role caches and confirms the intended identity.
- [ ] Offline tests cover entry transitions, source-session classifications, cancellation, non-interactive behavior, and preservation of caller environment; Terraform and IAM tests pass.
- [ ] The reviewed bootstrap plan contains only the intended trust and role-duration changes; AWS apply and live checks occur only through the existing approval workflow.
- [ ] Documentation explains installation, the manual command, local ARN setup, independent source and role expiry, troubleshooting, and rollback. No account-specific ARN, account ID, credential, or MFA code is committed.

## Decisions

- **Yes:** use an interactive zsh hook and preserve direnv for profile selection; interactive authentication has a separate lifecycle.
- **Yes:** renew on entry only for a missing or explicitly expired source session; a valid session needs no new MFA code.
- **Yes:** provide a manual refresh command for expiry while already inside the project.
- **Yes:** use three-hour source sessions and extend the MFA-age ceiling to three hours; keep assumed-role sessions at one hour, which is AWS's cap for role-chaining sessions.
- **No:** infer expiration from network or authorization failures; report the uncertainty instead.
- **No:** migrate to IAM Identity Center or expand IAM permissions as part of this change.

## Risks

| Risk                                                                  | Mitigation                                                                                                                 |
| --------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------- |
| A role profile that requests more than one hour fails the assumption. | Role profiles request one hour; the three-hour source session is reused for hourly assumptions with no new MFA code.       |
| A cached role masks an expired or broken source session.              | Check `gootip-mfa` directly and force fresh role assumptions for live verification.                                        |
| A failed trust-policy rollout blocks operator access.                 | Apply only a reviewed bootstrap plan and retain the documented one-hour recovery path and rollback.                        |
| Automatic checks run without network or a terminal.                   | Bound the check, report unknown failures without prompting, and skip interactive behavior outside an interactive terminal. |
| Hook ordering interferes with direnv or inherited AWS credentials.    | Isolate subprocess environments and test entry, exit, nested directories, and unchanged parent variables.                  |

## What is **not** in this spec

- AWS SSO or IAM Identity Center migration.
- Automatic resource deployment, new AWS permissions, and MFA seed storage.
